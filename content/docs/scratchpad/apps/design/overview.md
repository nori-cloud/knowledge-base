> Status: designed but not implemented. Archived for future reference.

## Goal

When a PR modifies source code for a specific workload (e.g., `factory/apps/outpost/`), spin up an ephemeral preview deployment in the **same dev namespace** (`nori-cloud-dev`) with unique resource names to avoid collisions with the existing dev instance.

## Architecture

### Repos Involved

| Repo                 | Role                                                           |
| -------------------- | -------------------------------------------------------------- |
| `nori-cloud/factory` | CI triggers (PR open/close), docker build, manifest generation |
| `nori-cloud/apps`    | GitOps manifests — template base + per-PR overlay directories  |
| `nori-cloud/infra`   | ArgoCD ApplicationSet for preview overlays                     |

### Template Structure

```
nori-cloud/apps/preview/
  base/                                ← Generic template, never applied directly
    deployment.yaml                    ← PLACEHOLDER_APP, PLACEHOLDER_IMAGE, etc.
    service.yaml
    ingress.yaml                       ← Tailscale ingress
    kustomization.yaml
  overlays/                            ← Per-PR instances, generated by CI
    outpost-pr-123/
      deployment.yaml                  ← Placeholders replaced with actual values
      service.yaml
      ingress.yaml
      kustomization.yaml               ← namespace: nori-cloud-dev
    vesta-pr-124/
      ...
```

### Placeholder Replacement

CI copies `base/*.yaml` to `overlays/<app>-pr-<N>/` and runs `sed`:

| Placeholder               | Replaced with                                             |
| ------------------------- | --------------------------------------------------------- |
| `PLACEHOLDER_APP`         | `<app>-pr-<N>` (used as resource name, labels, selectors) |
| `PLACEHOLDER_IMAGE`       | `ghcr.io/nori-cloud/<app>:pr-<N>-<sha>`                   |
| `PLACEHOLDER_PORT`        | App port (from detect-changes metadata)                   |
| `PLACEHOLDER_HOST`        | `<app>-pr-<N>.hoki-sole.ts.net`                           |
| `PLACEHOLDER_SECRET_NAME` | Existing dev ExternalSecret target name                   |
| `PLACEHOLDER_HEALTH_PATH` | App health check path                                     |

### Per-App Metadata

Added to `factory/.github/actions/detect-changes/action.yaml`:

```json
{
  "app": "outpost",
  "deploy": true,
  "paths": ["apps/outpost/**", "packages/**"],
  "previewPort": 3000,
  "previewSecretName": "outpost-secret",
  "previewHealthPath": "/api/healthz"
}
```

## CI Flow

### Deploy (PR open/sync)

**`preview-deploy.yaml`** in `nori-cloud/factory`:

1. Trigger: `pull_request: [opened, synchronize, reopened]` → `main`
2. `detect-changes` — finds changed apps
3. Per changed app (matrix):
   - Check preview metadata exists (port, secretName) — skip if missing
   - Build docker image, push to ghcr.io with tag `pr-<N>-<sha>`
   - Clone `nori-cloud/apps`, copy `base/` → `overlays/<app>-pr-<N>/`, replace placeholders
   - Commit and push to `nori-cloud/apps`
   - PR comment: `Preview deployed → https://<app>-pr-<N>.hoki-sole.ts.net`

### Cleanup (PR close)

**`preview-cleanup.yaml`** in `nori-cloud/factory`:

1. Trigger: `pull_request: [closed]`
2. Clone `nori-cloud/apps`
3. Delete `apps/preview/overlays/*-pr-<N>/` directories
4. Commit and push

### ArgoCD

**ApplicationSet** (`nori-cloud/infra/argo-cd/nori-cloud/preview-appset.yaml`):

```yaml
spec:
  syncPolicy:
    applicationsSync: create-delete # auto-delete orphaned apps
  generators:
    - git:
        directories:
          - path: "apps/preview/overlays/*"
  template:
    metadata:
      name: "{{path[3]}}-nori-cloud-preview"
    spec:
      destination:
        namespace: nori-cloud-dev
```

- Generates one ArgoCD Application per overlay directory
- `applicationsSync: create-delete` ensures apps are deleted when overlay directory is removed
- `prune: true` ensures k8s resources are deleted

## Key Design Decisions

1. **Same namespace** (`nori-cloud-dev`) — reuses existing ExternalSecret, SecretStore, no new namespace setup
2. **Unique resource names** — `<app>-pr-<N>` as resource name avoids collisions with real dev resources
3. **Reuse dev secrets** — preview Deployment's `secretRef.name` points to the real dev ExternalSecret target (e.g., `outpost-secret`)
4. **Template base** — one generic template for all apps, CI customizes via placeholder replacement (scales to any workload)
5. **Standalone preview app** — `apps/preview/` is separate from workload directories, no pollution of existing overlays

## Why It Was Dropped

The `feature → dev → main` branch promotion strategy (see `deployment-pipeline.md`) was chosen instead. Each feature branch gets PR'd into `dev` where it's built and deployed to the shared dev environment. After testing, `dev` is promoted to `main` for production.

The preview environment adds operational overhead (ArgoCD cleanup, image tag lifecycle, secret duplication concerns) that isn't justified given the existing dev environment already provides adequate integration testing.

## Revisiting

If preview environments become necessary, the template files and CI workflows provide a solid foundation. Key tasks to revisit:

1. Place `preview/base/` in `nori-cloud/apps` (remove the placeholder-removal infra)
2. Add `preview-appset.yaml` to ArgoCD config
3. Add `preview-deploy.yaml` and `preview-cleanup.yaml` to factory CI
4. Update `detect-changes` action with preview metadata for all supported apps
